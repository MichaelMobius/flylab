# FlyLab v1.1 — Adaptive Locomotion

## Core change

MaleCNS Control no longer has to translate a desired forward speed directly into body translation. When **Aprendizaje motor** is enabled, the descending-neuron readout is treated as locomotor intent and the body velocity is generated by a simplified stance-foot traction model.

## Added

- `src/adaptive/motor_learning.js`: online SPSA residual motor learner.
- Learned residual parameters around the innate tripod prior:
  - cadence scale;
  - amplitude scale;
  - duty-cycle offset;
  - inter-tripod phase residual;
  - turn gain;
  - lift scale.
- `tripodPropulsion()` in `src/gait.js`: computes forward/left/right propulsion from stance-foot kinematics.
- Effective displacement, rather than the internal speed state, is used to score command tracking.
- Slip proxy based on disagreement among stance-foot push velocities and effective body progress.
- Motor-learning UI with generation, mean reward, slip and learned policy values.
- Explicit reset for motor learning. A normal new trial preserves motor learning within the current page session.
- Session JSON includes `motorLearning` state and per-sample adaptive status.

## Experimental controls

- **Aprendizaje motor off:** calibrated v1.0.2 direct body command remains available as a baseline.
- **Aprendizaje motor on + MaleCNS Control:** DN command -> adaptive CPG -> stance traction -> body.
- Proxy and MaleCNS Observe remain unchanged.

## Scientific boundary

The traction model is intentionally lightweight. It makes the gait causal for displacement, but it is not a full rigid-body musculoskeletal reconstruction. No fruit coordinate, nutritive reward or distance-to-food signal enters the motor learner.
